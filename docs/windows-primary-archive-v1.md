# آرشیو اصلی ویندوز و بافر رزبری — نسخهٔ ۱

**به‌روزرسانی محل داده:** مسیر اصلی اکنون `F:\_HomaData\database\homa_telemetry.db` و پشتیبان‌ها در `F:\_HomaData\backups` است. مسیر AppData در توضیحات اولیهٔ پایین، مسیر قبل از انتقال است؛ فقط فایل‌های خصوصی اتصال هنوز در AppData هستند.

## مسئولیت‌ها

- ESP همان قرارداد قدیمی و بروکر داخلی `192.168.1.55:1883` را حفظ می‌کند.
- فقط رزبری درخواست دوره‌ای Info را طبق فاصلهٔ هر ماژول می‌فرستد.
- ویندوز به API رزبری روی پورت 8080 وصل می‌شود؛ MQTT مستقیم و درخواست تاریخچه از تبلت در مسیر اصلی اپ حذف شده‌اند.
- آرشیو دائمی روی کامپیوتر است: `%APPDATA%\Homa\homa_telemetry.db`؛ در این سیستم `C:\Users\Sobhan\AppData\Roaming\Homa\homa_telemetry.db`.
- با بازبودن اپ، هر ۱۰ ثانیه دادهٔ جدید و داده‌های جاافتاده به آرشیو منتقل می‌شوند. این زمان، بازهٔ همگام‌سازی بافر است، نه بازهٔ نمونه‌برداری ماژول.
- دادهٔ ویندوز خودکار پاک نمی‌شود. خاموشی یا بسته‌بودن اپ، ثبت رزبری را متوقف نمی‌کند. بعد از بازشدن اپ و اتصال دوباره، ادامه از آخرین COMMIT است.

## تضمین انتقال

۱. ویندوز شناسهٔ مصرف‌کنندهٔ پایدار خودش را ثبت می‌کند. منبع یک `stream_id` دارد تا شناسهٔ مشابه از نصب دیگر با دادهٔ قبلی اشتباه نشود.
۲. صفحه‌های حداکثر ۲۰۰ رکورد، با زمان اصلی منبع، متن اصلی و شناسهٔ اصلی دریافت می‌شوند.
۳. رکوردها، مقادیر قابل‌تحلیل و checkpoint در یک تراکنش SQLite نوشته می‌شوند.
۴. فقط بعد از COMMIT، تأیید دریافت به رزبری فرستاده می‌شود. قطع برق یا شبکه پیش از آن، باعث جلو رفتن کاذب checkpoint نمی‌شود؛ شکست ACK با تلاش مجدد بازیابی می‌شود.
۵. رزبری دادهٔ تأییدنشده را از پاک‌سازی سنی یا سقف تعدادی مستثنا می‌کند. دادهٔ تأییدشده مطابق سیاست بافر موجود (فعلاً ۳۰ روز، سقف ۲۰۰هزار رکورد) قابل پاک‌سازی است؛ حذف فوری انجام نمی‌شود تا پنل محلی هم دادهٔ اخیر داشته باشد.

این حفاظت از زمان ثبت اولین مصرف‌کننده فعال می‌شود؛ داده‌ای که پیش‌تر از بافر حذف شده قابل بازسازی نیست. کارت حافظه و دیسک ظرفیت نامحدود ندارند؛ خاموشی بسیار طولانی، خرابی کارت و حذف دستی داده تضمین نرم‌افزاری ندارند. پشتیبان روی همان دیسک، جای نسخهٔ خارج از دستگاه را نمی‌گیرد.

## ورود و استفاده

در اپ جدید، آدرس رزبری `192.168.1.55` و پورت `8080` است. نام کاربری و رمز **پنل** برای ورود اول استفاده می‌شود؛ رمز بروکر نیست. توکن نشست خصوصی در `%APPDATA%\Homa\raspberry-session.json` ذخیره می‌شود و رمز نوشته نمی‌شود. اجرای بعدی با نشست معتبر خودکار وصل می‌شود. بعد از انقضای نشست یا تغییر رمز پنل، ورود دوباره لازم است.

شبکهٔ فعلی HTTP محلی و MQTT بدون رمز دارد؛ برای LAN قابل اعتماد است و نباید مستقیم به اینترنت منتشر شود. تبلت و سایر کلاینت‌های قدیمی هنوز مرحلهٔ مهاجرت جدا دارند.

## ساختار قابل استفاده برای تحلیل

| جدول یا View | کاربرد |
|---|---|
| archive_records | دادهٔ اصلی؛ کلید `(stream_id,remote_id)`، نام ماژول، زمان Unix ثانیه‌ای، payload و parsed |
| archive_values | مقادیر هر فیلد پیام با ستون‌های numeric_value و text_value؛ بدون حدس واحد |
| archive_measurements | View اتصال دادهٔ اصلی به مقادیر؛ مناسب تحلیل و نمودار |
| archive_modules | آخرین نام و تنظیمات ماژول‌ها از رزبری |
| archive_checkpoints | آخرین رکورد ثبت قطعی هر منبع |
| telemetry / app_settings | داده‌ها و تنظیمات قدیمی؛ هنگام ارتقا حفظ شده‌اند |

نمونهٔ SQL خواندنی:

```sql
SELECT module_id,
       datetime(received_at, 'unixepoch') AS received_utc,
       numeric_value AS temperature
FROM archive_measurements
WHERE module_id = 'refrigerator' AND metric = 'TempIn'
ORDER BY received_at;
```

برای تحلیل می‌توان از SQLite استاندارد، Python یا ابزار خواندن SQLite استفاده کرد. هنگام بازبودن اپ، اتصال تحلیلی را فقط خواندنی بگیرید. برای پشتیبان سازگار، به‌جای کپی فایلِ در حال نوشتن اجرا کنید:

```powershell
python F:\Homa\automation\backup_windows_database.py
```

## APIهای اضافه‌شده

- رزبری: `POST /api/archive/register` با consumer؛ `GET /api/archive/page` با consumer/after/through/limit؛ `POST /api/archive/ack` با consumer/stream_id/after. همه نیازمند توکن پنل‌اند.
- ویندوز: `GET /v1/archive` برای مسیر دیتابیس، تعداد رکورد و checkpoint؛ `POST /v1/sync` برای تلاش فوری؛ `POST /v1/server/login` برای ورود پنل با username/password؛ `PUT /v1/settings` با server_host/server_port وقتی قطع است.
- تنظیم فاصلهٔ نمونه‌برداری ماژول: `PUT /v1/modules/refrigerator/settings` با poll_seconds؛ این تغییر در رزبری ذخیره می‌شود، نه تایمر مستقلی در ویندوز.
- تاریخچه: `GET /v1/history` همچنان دیتابیس ویندوز را می‌خواند؛ module اختیاری و پیش‌فرض refrigerator است.

توکن‌ها و رمزها در پاسخ وضعیت یا گزارش آزمون چاپ نمی‌شوند. رابط کنترل ویندوز همچنان loopback و توکن‌دار است.
