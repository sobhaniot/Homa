# قرارداد همگام‌سازی تاریخچهٔ تبلت و ویندوز ـ نسخهٔ ۱

**وضعیت:** پیاده‌سازی آزمایشی برای بروکر عمومی؛ مناسب دادهٔ حساس یا محصول نهایی نیست.

## هدف

تبلت Android 4.4 پاسخ‌های قدیمی یخچال را بدون تغییر Firmware دریافت و در SQLite خود ذخیره می‌کند. اپ Flutter ویندوز هنگام اتصال به بروکر، بازه‌ای را که هنوز در SQLite ویندوز ندارد از تبلت می‌خواهد. سپس نمودار از دادهٔ محلی ویندوز ساخته می‌شود.

## تاپیک‌ها

```text
/eleknow.com/nahbos5672730/home/history/request
/eleknow.com/nahbos5672730/home/history/response
```

این topicها مستقل از قرارداد قدیمی یخچال هستند:

```text
/eleknow.com/nahbos5672730/home/refrigerator
/eleknow.com/nahbos5672730/home/refrigeratorResult
```

هیچ topic یا payloadی در فریم‌ور قدیمی تغییر نمی‌کند.

## درخواست صفحه

ویندوز درخواست زیر را با QoS 0 و بدون Retain منتشر می‌کند:

```json
{
  "type": "HistoryRequest",
  "requestId": "شناسه یکتای درخواست",
  "from": 1790000000000,
  "to": 1791000000000,
  "offset": 0,
  "limit": 100
}
```

`from` و `to` زمان Unix برحسب میلی‌ثانیه هستند. `limit` در تبلت حداکثر ۱۰۰ رکورد است. تبلت فقط در زمانی که برنامه باز و به MQTT متصل باشد درخواست را پاسخ می‌دهد.

## پاسخ صفحه

تبلت همان `requestId` را در پاسخ نگه می‌دارد:

```json
{
  "type": "HistoryBatch",
  "requestId": "شناسه یکتای درخواست",
  "offset": 0,
  "nextOffset": 100,
  "hasMore": true,
  "items": [
    {
      "receivedAt": 1790000000000,
      "payload": {"TempIn": 4.5, "TempOut": 22}
    }
  ]
}
```

تا وقتی `hasMore` برابر `true` باشد، ویندوز همان بازه و شناسه را با `offset = nextOffset` دوباره درخواست می‌کند. رکوردهای تکراری در دیتابیس مقصد با ترکیب ماژول، زمان دریافت و payload حذف می‌شوند.

## مرز اعتماد

بروکر آزمایشی عمومی است و MQTT روی پورت ۱۸۸۳ رمزنگاری یا ACL ندارد. هر شخصی که topicها را بداند ممکن است درخواست را مشاهده یا پاسخ جعلی منتشر کند. این مسیر صرفاً نمونه‌سازی است؛ برای استفادهٔ خانگی واقعی باید بروکر خصوصی، TLS، هویت مستقل دستگاه و مجوز topic محدود اضافه شود.
