# کنترل برنامه‌ای اپ ویندوز — مرحلهٔ ۱۱

به‌روزرسانی معماری: مسیر پیش‌فرض اپ اکنون API رزبری و آرشیو دائمی ویندوز است. `GET /v1/archive`، `POST /v1/sync` و `POST /v1/server/login` اضافه شده‌اند. پورت اتصال اپ به رزبری 8080 است، نه 1883. تنظیم آدرس با server_host/server_port و تنظیم فاصلهٔ نمونه‌برداری با `/v1/modules/refrigerator/settings` انجام می‌شود. راهنمای فعلی در `F:\Homa\docs\windows-primary-archive-v1.md` است؛ بخش «مرز مراحل» پایین سابقهٔ مرحلهٔ قبل است.

این API داخل خود اپ Flutter اجرا می‌شود؛ بدون موس، کیبورد، کنترل دسکتاپ یا ابزار جانبی. برنامه باید باز باشد. اتصال فقط روی `127.0.0.1:17863` است و از دستگاه‌های دیگر قابل دسترسی نیست. هر بار اجرای اپ توکن تصادفی تازه می‌سازد؛ مشخصات اتصال در `%APPDATA%\Homa\control-api.json` قرار می‌گیرد. این فایل خصوصی است؛ آن را منتشر نکنید. برنامه‌های دارای دسترسی به حساب ویندوز شما می‌توانند آن را بخوانند. درخواست دارای هدر Origin مرورگر رد می‌شود.

فراخوانی با Python موجود روی کامپیوتر:

```powershell
python F:\Homa\automation\homa_control.py GET /v1/status
python F:\Homa\automation\homa_control.py GET /v1/messages
python F:\Homa\automation\homa_control.py GET '/v1/history?from=2026-10-01T00:00:00Z&to=2026-10-23T00:00:00Z&limit=100'
python F:\Homa\automation\homa_control.py PUT /v1/chart --data '{"period":"7d"}'
```

برای کلاینت دیگر، توکن فایل را در هدر `Authorization: Bearer <token>` قرار دهید. پاسخ JSON است و جزئیات احراز هویت در پاسخ وضعیت یا پیام‌ها بازگردانده نمی‌شود.

| روش و مسیر | رفتار |
|---|---|
| GET /v1/status | اتصال، وضعیت واقعی اپ، آخرین مقادیر یخچال، تنظیمات و بازهٔ نمودار |
| GET /v1/messages | حداکثر ۱۰۰ پیام وضعیت همین اجرای اپ |
| GET /v1/history | تاریخچهٔ دیتابیس ویندوز؛ from و to به شکل ISO، limit از ۱ تا ۶۰۰ |
| PUT /v1/chart | تغییر همان نمودار نمایش‌داده‌شده؛ period یکی از 1h،24h،7d،30d |
| PUT /v1/settings | ذخیره و نمایش broker_host،broker_port،poll_seconds؛ فقط وقتی اتصال قطع است؛ هیچ فرمان دستگاهی نمی‌فرستد |
| POST /v1/connect | اتصال واقعی اپ به بروکر تنظیم‌شده؛ رفتار فعلی دریافت دوره‌ای اپ را فعال می‌کند |
| POST /v1/disconnect | قطع اتصال همان اپ |
| POST /v1/modules/refrigerator/request | ارسال Info خواندنی؛ نیازمند اتصال |
| POST /v1/modules/refrigerator/parameters | فرمان واقعی با temperature،hysteresis و confirm:true؛ بدون تأیید صریح رد می‌شود |

فرمان پارامترها واقعی است و فقط با اجازهٔ مالک استفاده شود. `queued:true` به معنای تأیید اعمال روی یخچال نیست. فرمان shell، دسترسی فایل دلخواه و انتشار MQTT دلخواه وجود ندارد. فقط ماژول یخچال که فعلاً در اپ پیاده شده پشتیبانی می‌شود.

## مرز مراحل

مرحلهٔ ۱۱: کنترل خود اپ از API محلی + API مستقل رزبری موجود است؛ MCP الزامی نیست چون API انتخاب شده است. این رابط تاریخچهٔ فعلی ویندوز را می‌خواند، نه اینکه ادعا کند همگام‌سازی با رزبری انجام شده است.

مرحلهٔ ۱۲ و ۱۳: جایگزینی سرویس قدیمی MQTT/تبلت با API رزبری و همگام‌سازی خودکار آرشیو، هنوز کار جداگانه است. API فعلی اپ همان تنظیمات و رفتار فعلی اپ را کنترل می‌کند؛ در تست مرحلهٔ ۱۱ اتصال واقعی یا فرمان تنظیم یخچال ارسال نمی‌شود.

برای اجرا، کل پوشهٔ Release لازم است؛ فایل exe به تنهایی کافی نیست:

`F:\Homa\software\windows\build\windows\x64\runner\Release\homa_control.exe`
