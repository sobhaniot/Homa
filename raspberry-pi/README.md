# سرور محلی هما — نسخهٔ ۱

## وضعیت فعلی دسترسی و داده‌ها

آدرس فعلی `192.168.1.55` است. طبق درخواست مالک، ورود پنل وب و VNC بدون رمز شده؛ دسکتاپ از قبل autologin دارد و SSH این کامپیوتر با کلید بدون تایپ رمز متصل می‌شود. رمز حساب لینوکس/مدیریت sudo حذف نشده است. این سرویس‌ها مخصوص LAN مورد اعتمادند؛ پورت‌های 8080،5900 و1883 را به اینترنت منتشر نکنید. مقادیر رمزدار و آدرس .12 در بخش‌های اولیهٔ پایین، سابقهٔ تنظیم قبلی‌اند.

دیتابیس اصلی کامپیوتر اکنون `F:\_HomaData\database\homa_telemetry.db` است؛ رزبری بافر تأییدشونده است. `web_auth_required` در جدول settings رزبری روی false قرار گرفته است. نسخهٔ تنظیم VNC پیش از تغییر کنار `/etc/wayvnc/config` با پسوند `.auth-backup-...` حفظ شده است. کلیدهای SSH و رمز مدیریتی تغییری نکرده‌اند.

پنل فارسی: `http://192.168.1.12:8080` · رزبری‌پای ۳ مدل B · Debian 13 / Python 3.13.

## ساختار

- `server.py`: API، SQLite، جمع‌کنندهٔ MQTT، دریافت دوره‌ای مستقل و اشتراک بیرونی انتخابی.
- `web/`: پنل سادهٔ فارسی با JavaScript ES5 و XHR؛ بدون CDN یا اینترنت برای نمایش رابط.
- `deploy.py`: نصب سرویس‌های خودکار، کاربر محدود homa و تولید رمزهای مستقل در اولین اجرا.
- `backup_database.py`: تهیهٔ پشتیبان سازگار از SQLite فعال در `/var/backups/homa`؛ اجرا با sudo.
- `tests/test_server.py`: آزمون قرارداد و کنترل دسترسی، اعتبارسنجی و ذخیره‌سازی.
- `tests/test_mqtt.py`: آزمون با ماژول شبیه‌سازی‌شده روی تاپیک‌های اختصاصی؛ هیچ تغییر عملیاتی در یخچال ندارد.
- `tests/check_deployment.py`: بررسی دریافت واقعی یخچال، سلامت پایگاه داده و حفظ تاریخچه پس از restart سرویس.
- `tests/check_after_boot.py`: بررسی بدون sudo از API پس از بوت و رد MQTT ناشناس.
- `TEST_REPORT.md`: نتیجهٔ آزمون روی برد واقعی و مواردی که هنوز آزموده نشده‌اند.
- `bootstrap_packages.py`: راه جایگزین دریافت بسته‌های رسمی با تطبیق SHA256 فهرست apt.
- `.local/`: فایل‌های فقط همین کامپیوتر مانند اطلاعات ورود و بسته‌های دانلودشده؛ از Git خارج است.

## روی برد

- برنامه: `/opt/homa`؛ فایل اصلی پروژه در ویندوز: `F:\Homa\raspberry-pi`.
- پایگاه داده: `/var/lib/homa/homa.sqlite3` با حالت WAL و زمان دریافت سرور به شکل Unix UTC.
- رمزها: `/etc/homa/credentials.json` و `/etc/homa/server.env`، فقط قابل‌خواندن توسط root.
- اطلاعات ورود مالک: `/home/sobhan/Homa-access.txt` و نسخهٔ روی Desktop، با مجوز 600.
- سرویس‌ها: `homa.service` و `mosquitto.service`، هر دو هنگام بوت فعال‌اند.
- MQTT محلی: پورت 1883، کاربر `homa`؛ اتصال ناشناس بسته است.
- وب: پورت 8080، کاربر `admin` و رمز جدا از رمز ورود لینوکس.

اجرای دوبارهٔ `sudo python3 deploy.py` رمزها و پایگاه دادهٔ قبلی را حفظ می‌کند. پیش‌نیازها: `mosquitto mosquitto-clients python3-paho-mqtt` از مخزن رسمی سیستم. در شبکهٔ فعلی دانلود apt روی برد مشکل داشت؛ بسته‌ها از کامپیوتر دریافت و با SHA256 فهرست مخزن تطبیق داده شدند. منابع apt از HTTP به HTTPS رسمی تبدیل شدند و فایل‌های قبلی با پسوند `.homa-http-backup` باقی‌اند.

## رفتار ماژول‌ها

یخچال قدیمی با همان قرارداد موجود تنظیم شده است:

- درخواست: `/eleknow.com/nahbos5672730/home/refrigerator`
- پاسخ: `/eleknow.com/nahbos5672730/home/refrigeratorResult`
- درخواست خواندنی: `{"type":"Info"}`؛ پیش‌فرض هر ۳۰ ثانیه، قابل تنظیم برای هر ماژول.
- فعلاً مسیر یخچال **خارجی** است چون فریم‌ور موجود به test.mosquitto.org وصل است.
- انتقال به حالت محلی نیازمند تغییر آدرس بروکر در تنظیمات خود ماژول و سپس تغییر مسیر آن در پنل است؛ فریم‌ور یا تنظیمات فعلی ماژول در این مرحله تغییر نکرده‌اند.
- ذخیرهٔ دما و هیسترسیس در فرم صرفاً ذخیرهٔ مقدار پیشنهادی است. ارسال واقعی دکمه و تأیید جداگانه دارد و در آزمون‌های استقرار انجام نشده است.
- `tx` یعنی کتابخانهٔ MQTT ارسال را پذیرفته است، نه تأیید اجرای فرمان در دستگاه. قرارداد قدیمی شناسهٔ تأیید ندارد.
- وضعیت آنلاین به پاسخ تازه وابسته است؛ بدون پاسخ یا پاسخ قدیمی، ماژول آنلاین نشان داده نمی‌شود.
- پیام retained هنگام اشتراک جدید در پیام خام ثبت می‌شود ولی اندازه‌گیری تازه یا آنلاین‌بودن ایجاد نمی‌کند.
- پیام «اتصال یخچال به MQTT» در لاگ خام دیده می‌شود ولی سنجش دما نیست. رکوردهای اولیهٔ چنین پیام‌هایی به‌صورت غیرحذفی `is_sample=0` علامت خورده‌اند؛ متن و شناسهٔ آن‌ها در پایگاه داده باقی است.
- درخواست دوره‌ای فعلاً فقط Info است. برای قرارداد غیر از آن، باید مبدل خواندنی جدید در سرور اضافه شود.

## ارتباط با بروکر خارجی

هیچ Bridge عمومی دوطرفه‌ای وجود ندارد. گزینهٔ هر ماژول:

1. `off`: هیچ انتشار اضافی بیرونی از طرف سرور انجام نمی‌شود. دریافت از بروکر خارجی برای ماژولی که هنوز روی آن است، مستقل از این گزینه است.
2. `on_demand`: درخواست `{"type":"Info"}` روی `homa/<installation>/modules/<id>/request`، آخرین دادهٔ ذخیره‌شده را روی همان مسیر با پسوند `/state` برمی‌گرداند. در صورت قدیمی‌بودن داده، درخواست تازه نیز صف می‌شود؛ پاسخ تازه هنگام رسیدن ارسال می‌شود. زمان دریافت همراه پاسخ است.
3. `continuous`: هر پاسخ تازه به `/state` بیرونی هم ارسال می‌شود.

شناسهٔ نصب در پنل بخش بروکر نشان داده می‌شود. درخواست بیرونی retained، قالب Param و پیام بیش از ۱۶ کیلوبایت پذیرفته نمی‌شود. برای هر ماژول درخواست بیرونی حداقل ۵ ثانیه فاصله دارد. بروکر عمومی احراز هویت مشتری نهایی ندارد؛ اشتراک بیرونی اختیاری و پیش‌فرض خاموش است. این مکانیسم اطلاعات را منتقل می‌کند و حضور گوشی خارج از خانه را خودکار تشخیص نمی‌دهد.

## API نسخهٔ ۱

`POST /api/login` با JSON شامل `username` و `password` و گزینهٔ اختیاری `remember:true`، توکن نشست و `expires` برمی‌گرداند. سپس هدر `Authorization: Bearer <token>` لازم است. نشست معمولی ۱۲ ساعت و نشست به‌خاطرسپرده‌شده ۳۰ روز اعتبار دارد و پس از restart سرور هم معتبر می‌ماند. در پایگاه داده فقط SHA256 توکن ذخیره می‌شود. مرورگر با انتخاب «مرا به خاطر بسپار»، توکن را در localStorage و در حالت معمول در sessionStorage نگه می‌دارد؛ رمز ذخیره نمی‌شود. `POST /api/logout` نشست جاری را در سرور لغو می‌کند و مرورگر توکن را پاک می‌کند. رمز در پاسخ تنظیمات و لاگ HTTP برنمی‌گردد. تلاش ناموفق ورود برای هر IP محدود است.

| روش و مسیر | کاربرد |
|---|---|
| `GET /api/health` | سلامت عمومی بدون اطلاعات خصوصی |
| `POST /api/logout` | لغو نشست جاری |
| `GET /api/status` | وضعیت بروکرها، فضای حافظه و زمان اجرای سرویس |
| `GET /api/modules` | تنظیمات، آخرین داده و تازگی پاسخ هر ماژول |
| `PUT /api/modules` | افزودن یا ویرایش ماژول؛ شناسهٔ یکتا و تاپیک‌های مشخص |
| `DELETE /api/modules/<id>` | حذف تنظیمات؛ تاریخچه باقی می‌ماند |
| `POST /api/modules/<id>/request` | صف‌کردن Info خواندنی |
| `POST /api/modules/<id>/parameters` | فقط یخچال: `temperature`، `hysteresis` و `confirm:true`؛ فرمان واقعی |
| `GET /api/messages?module=<id>&after=<id>&limit=200` | صفحه‌بندی پیام‌های خام؛ بدون after آخرین ۲۰۰ پیام |
| `GET /api/history?module=<id>&after=<id>&limit=200&from=<unix>&to=<unix>&through=<id>` | تاریخچهٔ پایدار برای ویندوز؛ cursor شناسه‌ای |
| `GET /api/config` | تنظیمات سرور و بروکر با رمز پنهان |
| `PUT /api/config` | تنظیمات `external` و `retention_days`؛ حذف فیلد password رمز قبلی را حفظ می‌کند؛ رشتهٔ خالی آن را پاک می‌کند |

پاسخ صفحه‌بندی شامل `items` و `next_after` است. برای همگام‌سازی افزایشی، ویندوز آخرین شناسهٔ ذخیره‌شده را نگه دارد؛ شناسه‌ها monotonic هستند. به‌دلیل سیاست نگهداری، بازه‌های حذف‌شده قابل بازیابی از API نیستند. سقف هر صفحه ۵۰۰ رکورد است. نگهداری تاریخچه پیش‌فرض ۳۰ روز/حداکثر ۲۰۰هزار رکورد و پیام خام حداکثر ۷ روز/۵۰هزار رکورد است؛ هر کدام زودتر برسد. پاک‌سازی هر ساعت اجرا می‌شود.

نمایش زمان در پنل شمسی، با ارقام فارسی و به وقت تهران است. تقویم محلی با `jalaali-js` نسخهٔ ثابت 1.2.8 (MIT، مجوز در `web/LICENSE.jalaali-js`) کار می‌کند؛ منبع: https://github.com/jalaali/jalaali-js . فیلتر تاریخ، پس از تبدیل شمسی به میلادی، پارامترهای `from_date=YYYY-MM-DD` و `to_date=YYYY-MM-DD` را می‌فرستد. سرور مرز روز را با ZoneInfo تهران حساب می‌کند؛ `to_date` شامل تمام روز پایان است. API قدیمی Unix همچنان پشتیبانی می‌شود. مسیر بدون Intl برای مرورگر قدیمی، ساعت ثابت ایران از ۲۰۲۳ به بعد را پوشش می‌دهد؛ برای واردکردن دادهٔ قدیمی‌تر باید مرورگر دارای Intl استفاده شود یا تبدیل نمایش سمت سرور توسعه یابد.

این API برای کنترل برنامه‌ای توسط دستیار نیز قابل استفاده است؛ MCP اختصاصی هنوز اضافه نشده است. پنل HTTP برای LAN است، نه انتشار مستقیم روی اینترنت؛ دسترسی بیرونی پنل در این نسخه پیاده‌سازی نشده است.

## دامنهٔ مرحلهٔ فعلی

سرور و پنل مستقل روی برد اجرا می‌شوند. برنامه‌های موجود ویندوز و تبلت در این مرحله تغییر نکرده‌اند؛ برای اینکه **تمام** درخواست‌ها فقط از سرور ارسال شوند باید در مرحلهٔ بعد به API/بروکر محلی منتقل شوند و polling قبلی آن‌ها خاموش شود. همگام‌سازی خودکار تاریخچهٔ ویندوز از رزبری‌پای به این مرحلهٔ بعد وابسته است.

برای حفظ IP بهتر است در مودم DHCP Reservation تنظیم شود؛ پنل روتر در این مرحله تغییر نکرده است. مرورگر واقعی تبلت Android 4.4 هنوز آزموده نشده؛ رابط بدون fetch، Promise، ES6 و وابستگی بیرونی نوشته شده است.

## آزمون و نگهداری

```sh
python3 -m unittest discover -s tests -p test_server.py -v
sudo python3 tests/test_mqtt.py
sudo python3 tests/check_deployment.py
systemctl status homa mosquitto
journalctl -u homa --no-pager -n 50
```

آزمون deployment سرویس هما را یک‌بار restart می‌کند و فقط دادهٔ واقعی را می‌خواند. آزمون MQTT از پایگاه موقت و تاپیک‌های integration با شناسهٔ تصادفی استفاده می‌کند. برای پشتیبان پایگاه دادهٔ فعال، `sudo python3 backup_database.py` از SQLite backup استفاده می‌کند؛ کپی سادهٔ فایل اصلی بدون WAL روش مطمئنی نیست. پشتیبان‌گیری زمان‌بندی‌شدهٔ خارج از کارت هنوز تنظیم نشده است.
